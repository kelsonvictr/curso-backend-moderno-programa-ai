Serverless: uma função no console [03]
O código que só existe enquanto trabalha
O conceito: Serverless

Nome oficial: Serverless computing; na AWS, o serviço de funções se chama Lambda (o modelo é conhecido como FaaS, função como serviço).

O que diz: você entrega uma função e diz que evento a dispara. A nuvem liga uma máquina só quando o evento chega, roda a função e cobra pelo tempo que ela rodou.

Por que existe: a maior parte dos sistemas passa a maior parte do tempo parada. Um servidor ligado 24 h cobra pelas horas vazias e ainda pede cuidado: atualização, disco, segurança, queda.

Como reconhecer: o código não tem main nem servidor web subindo. Tem um método que recebe um evento e devolve uma resposta.

Cuidado: servidor existe, só não é seu. E a função que estava parada demora mais na primeira chamada: é a partida a frio (cold start).

A ideia

A Biblioteca recebe poucas visitas, quase todas à tarde. Em vez de um computador ligado esperando, vamos ter uma função que só existe durante cada pedido.

Regra: sem pedido, sem custo.

Antes de qualquer ferramenta, você vai criar uma função clicando no console da AWS, só para sentir o que é. Guarde a sensação dos cliques: ela é o problema do próximo passo.

IaC: a mesma função, escrita em arquivo [04]
A nuvem vira texto no repositório
O conceito: Infraestrutura como código

Nome oficial: Infrastructure as Code (IaC). Aqui a ferramenta é o Serverless Framework, que por baixo usa o CloudFormation da AWS.

O que diz: você descreve num arquivo o que deve existir na nuvem. Uma ferramenta compara o arquivo com o que existe e cria, muda ou apaga até os dois baterem.

Por que existe: infraestrutura criada no clique não se repete, não se revisa e não tem histórico. Ninguém sabe dizer por que aquela caixinha está marcada.

Como reconhecer: existe um arquivo no repositório (serverless.yml) e um comando (serverless deploy). Ninguém abre o console para criar nada.

Cuidado: o arquivo só manda no que ele criou. O que foi clicado por fora fica invisível para a ferramenta, e mexer no console no que o arquivo criou faz os dois divergirem.

A ideia

A ola-console existe, mas só você sabe como ela foi feita. Vamos criar a mesma função em Java, agora descrita num arquivo que qualquer pessoa (ou máquina) consegue executar.

Regra: se está na nuvem, está escrito no repositório.

DynamoDB: os livros ganham memória [05]
Uma tabela e a permissão mínima para usá-la
O conceito: DynamoDB e permissão mínima

Nome oficial: Amazon DynamoDB, um banco NoSQL de chave e valor. E IAM (Identity and Access Management), o serviço de permissões da AWS.

O que diz: no DynamoDB você cria uma tabela e escolhe a chave. Cada item é um conjunto de atributos achado pela chave. E no IAM, nada é permitido até alguém permitir: a função só toca na tabela se uma regra disser que pode.

Por que existe: um banco tradicional também é um servidor ligado 24 h. O DynamoDB cobra por leitura e escrita feitas, como a Lambda cobra por chamada. Os dois combinam.

Como reconhecer: não existe CREATE TABLE com colunas nem JOIN. Existe uma chave obrigatória (id) e o resto cada item traz o que quiser.

Cuidado: ler a tabela inteira (Scan) serve para um acervo de bairro, não para milhões de itens. E permissão larga (*) “para não dar erro” é como entregar a chave do prédio para quem só precisava de uma sala.

A ideia

A função não guarda nada entre uma chamada e outra: ela nasce, responde e some. A memória da Biblioteca precisa morar fora dela, numa tabela. E a função só recebe as duas ações que usa: gravar e listar.

Regra: cada função recebe só o que usa.

✏️ Desenhe antes de pedir

No seu docs/arquitetura.drawio, acrescente:

  • Uma tabela DynamoDB chamada livros, com setas das duas funções até ela.
  • Em cima das setas, o que cada uma pode fazer: PutItem e Scan. É o IAM no desenho.

# A infraestrutura da Biblioteca, escrita como texto.
# "serverless deploy" lê este arquivo e cria (ou atualiza) tudo na sua conta da AWS.
service: biblioteca-serverless
frameworkVersion: '3'

provider:
  name: aws
  runtime: java21
  region: us-east-1
  stage: dev
  memorySize: 1024
  timeout: 15
  environment:
    # As funções leem o nome da tabela daqui (System.getenv).
    TABELA_LIVROS: ${self:service}-${sls:stage}-livros
  iam:
    role:
      statements:
        # As funções só podem gravar e ler nesta tabela. Nada mais.
        - Effect: Allow
          Action:
            - dynamodb:PutItem
            - dynamodb:Scan
          Resource:
            Fn::GetAtt: [TabelaLivros, Arn]

package:
  # O jar que o "./mvnw package" gera.
  artifact: target/biblioteca-serverless.jar

functions:
  ola:
    handler: br.com.biblioteca.OlaHandler
    events:
      - httpApi: GET /ola
  cadastrarLivro:
    handler: br.com.biblioteca.CadastrarLivroHandler
    events:
      - httpApi: POST /livros
  listarLivros:
    handler: br.com.biblioteca.ListarLivrosHandler
    events:
      - httpApi: GET /livros

resources:
  Resources:
    TabelaLivros:
      Type: AWS::DynamoDB::Table
      Properties:
        TableName: ${self:service}-${sls:stage}-livros
        # Paga por leitura e escrita feitas. Parada, a tabela não custa nada.
        BillingMode: PAY_PER_REQUEST
        AttributeDefinitions:
          - AttributeName: id
            AttributeType: S
        KeySchema:
          - AttributeName: id
            KeyType: HASH
  • Em Action há só dynamodb:PutItem e dynamodb:Scan.
  • Em Resource está a tabela (TabelaLivros), não "*".
  • O nome da tabela aparece uma vez como regra e chega ao Java por TABELA_LIVROS.
  • O teste usa um repositório em memória: roda sem internet e sem AWS.

import java.util.Map;
import java.util.UUID;

import com.amazonaws.services.lambda.runtime.Context;
import com.amazonaws.services.lambda.runtime.RequestHandler;
import com.amazonaws.services.lambda.runtime.events.APIGatewayV2HTTPEvent;
import com.amazonaws.services.lambda.runtime.events.APIGatewayV2HTTPResponse;
import com.fasterxml.jackson.core.JsonProcessingException;
import com.fasterxml.jackson.databind.JsonNode;

/** POST /livros: confere o pedido, gera o id e guarda o livro. */
public class CadastrarLivroHandler implements RequestHandler<APIGatewayV2HTTPEvent, APIGatewayV2HTTPResponse> {

    private final LivroRepositorio livros;

    /** A Lambda usa este: liga no DynamoDB de verdade. */
    public CadastrarLivroHandler() {
        this(new LivroRepositorioDynamo());
    }

    /** Os testes usam este: entregam um repositório de mentira. */
    public CadastrarLivroHandler(LivroRepositorio livros) {
        this.livros = livros;
    }

    @Override
    public APIGatewayV2HTTPResponse handleRequest(APIGatewayV2HTTPEvent evento, Context contexto) {
        JsonNode corpo;
        try {
            corpo = Respostas.JSON.readTree(evento.getBody() == null ? "{}" : evento.getBody());
        } catch (JsonProcessingException e) {
            return Respostas.json(400, Map.of("erro", "O corpo precisa ser um JSON válido."));
        }

        String titulo = corpo.path("titulo").asText("").trim();
        String autor = corpo.path("autor").asText("").trim();
        if (titulo.isEmpty() || autor.isEmpty()) {
            return Respostas.json(400, Map.of("erro", "Informe titulo e autor."));
        }

        Livro livro = new Livro(UUID.randomUUID().toString(), titulo, autor);
        livros.salvar(livro);
        return Respostas.json(201, livro);
    }
}

O construtor que recebe o LivroRepositorio é o D do Cap 04: a função depende do contrato, e quem monta escolhe o detalhe. É isso que deixa o teste rodar sem AWS.

A página na Vercel e o CORS [06]
A Biblioteca ganha um rosto e esbarra no navegador
O conceito: CORS

Nome oficial: Cross-Origin Resource Sharing, compartilhamento de recursos entre origens.

O que diz: uma página só pode chamar, por JavaScript, uma API de outro endereço se essa API responder dizendo “esta origem pode”. Quem confere e bloqueia é o navegador.

Por que existe: sem essa regra, qualquer site aberto numa aba poderia chamar outras APIs em seu nome, usando a sua sessão.

Como reconhecer: no curl e no Insomnia funciona; na página, falha. O erro aparece no Console do navegador (F12), não na API.

Cuidado: a saída preguiçosa é liberar *, qualquer origem. Libere só o endereço do seu site.

Até agora só usa a Biblioteca quem sabe montar um pedido HTTP. Vamos dar uma página a ela, publicada na Vercel. Página e API moram em endereços diferentes, então o navegador vai barrar a conversa até a API autorizar.

Regra: quem bloqueia é o navegador; quem libera é a API.

CI/CD: o push publica [07]
O deploy sai do notebook e vai para a esteira
O conceito: CI/CD

Nome oficial: Continuous Integration e Continuous Delivery: integração contínua e entrega contínua. A ferramenta aqui é o GitHub Actions.

O que diz: CI: a cada mudança enviada, uma máquina limpa baixa o código, compila e roda os testes. CD: se passou, a mesma máquina publica. O roteiro inteiro é um arquivo no repositório.

Por que existe: deploy feito do notebook depende de uma pessoa, da máquina dela e da memória dela. Um dia alguém esquece o teste, e é numa sexta-feira.

Como reconhecer: existe uma pasta .github/workflows/ e ninguém do time roda deploy à mão. A aba Actions mostra cada publicação, com data, autor e resultado.

Cuidado: a esteira precisa da chave da AWS. Ela fica em Secrets, um cofre do repositório: dá para usar, não dá para ler de volta.

A ideia

O serverless deploy ainda mora no seu notebook. Vamos escrever o roteiro uma vez e deixar o GitHub executar a cada push: testa, empacota e publica.

Regra: quem publica é a esteira, e só o que passou no teste.

PalavraO que é
workflowO roteiro: um arquivo .yml em .github/workflows/.
gatilho (on)O que faz o roteiro rodar. Aqui: push na main.
runnerA máquina emprestada pelo GitHub. Nasce limpa e some no fim.
job e stepO trabalho e cada passo dele, em ordem. Falhou um, os seguintes não rodam.
secretUm valor guardado no cofre do repositório, entregue ao runner só na hora.

✏️ Desenhe antes de pedir

No seu docs/arquitetura.drawio, acrescente:

  • O GitHub (repositório + Actions), fora da AWS.
  • Seta do notebook para o GitHub: git push. Apague a seta serverless deploy do notebook para a AWS.
  • Seta do GitHub para a AWS: “Actions: testa e publica”. Seta do GitHub para a Vercel: “publica a página”.

BugZilla: os erros clássicos da nuvem [08]
Cinco jeitos de errar que você vai ver por aí (e em sugestões de agente)

Cinco erros que aparecem em projeto de verdade e em sugestão de agente. Para cada um: qual é o estrago e qual é o conserto?

🐛 1. A chave no repositório

“Coloquei a chave num .env só para testar.” Robôs acham chaves no GitHub em minutos. Conserto: Secrets. Se vazou, apague a chave no IAM na hora; apagar o commit não adianta.

🐛 2. O asterisco no IAM

Action: dynamodb:* e Resource: "*" “para não dar erro de permissão”. Uma função pública passa a poder apagar qualquer tabela da conta. Conserto: só as ações usadas, só na tabela dela.

🐛 3. O asterisco no CORS

allowedOrigins: '*' “para funcionar logo”. Qualquer site passa a poder chamar a sua API pelo navegador do visitante. Conserto: a origem exata do seu site.

🐛 4. O ajuste no console

“Só aumentei a memória da função lá no console.” O arquivo diz uma coisa, a nuvem outra, e o próximo deploy desfaz o ajuste sem avisar. Conserto: mude o arquivo e publique.

🐛 5. O deploy por fora da esteira

“Estava com pressa, rodei do notebook.” Vai ao ar código que não está no repositório e que não passou pelos testes. Conserto: depois que a esteira existe, só ela publica.

🐛 Bônus: a nuvem esquecida

Ninguém lembra o que está ligado na conta. Conserto: o que foi criado por arquivo se apaga com um comando. O que foi criado no clique… alguém lembra da ola-console?

Sem pedido, sem custo: a função só existe enquanto trabalha.

IaC

Infra escrita se refaz; infra clicada se perde.

IAM

Cada função recebe só o que usa.

CORS

Quem bloqueia é o navegador; quem libera é a API.

CI/CD

Quem publica é a esteira, e só o que passou no teste.

A frase do dia

Desenhe, peça, confira.

Você saiu de uma conta vazia para um sistema completo, e sabe desenhá-lo de cabeça:

🏠 Para casa

  1. Termine o desafio do DELETE, publicando só pela esteira.
  2. No draw.io: Arquivo → Exportar como → PNG, salve em docs/arquitetura.png e mostre o desenho no README.md. Repositório com desenho vale por dez sem.
  3. Escreva no README, com as suas palavras, uma frase para cada caixa do desenho: o que ela faz e por que está ali.
  4. Quando terminar, siga o passo 4 de “Desligar tudo”.
💡
Para quem quiser ir além: separar dev e prod com --stage; trocar a chave por OIDC; ligar o SnapStart para encurtar a partida a frio do Java; pôr um domínio próprio na API.
