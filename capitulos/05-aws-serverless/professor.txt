REGRAS QUE VOCÊ REPETE
  A chave vai da página da AWS direto para os Secrets do GitHub. Nunca em arquivo, notebook ou agente.
  Quem publica é a esteira. Ninguém roda deploy (nem tem como: não há chave no notebook).
  O agente não roda nada de nuvem nem git push.

SE ALGO DER ERRADO
  Conta AWS ainda ativando → aluno acompanha em dupla; não há atalho.
  Console em outra região → canto superior direito, N. Virginia (us-east-1).
  Actions "Credentials could not be loaded" → nome do Secret errado. "security token ... invalid" →
  valor colado errado: apagar a chave no IAM, criar outra, regravar os dois Secrets.
  "not authorized to perform: cloudformation:CreateStack" → faltou AdministratorAccess no usuário.
  Actions: ./mvnw Permission denied → git update-index --chmod=+x backend/mvnw (Windows).
  Internal Server Error → Lambda → função → Monitor → View CloudWatch logs. AccessDenied = iam;
  ResourceNotFound = nome da tabela; Task timed out after 6.00 seconds = faltou timeout: 15.
  Vercel 404 → Root Directory. CORS persiste → esteira ainda rodando, ou origem com barra/sem https.
  UPDATE_IN_PROGRESS → dois pushes seguidos; esperar e Re-run jobs.
  CloudFormation DELETE_FAILED → bucket de deploy não foi esvaziado no S3.
  O agente quis rodar deploy ou instalar a AWS CLI → pare, releia a regra 1 do AGENTS.md com a turma.

CINCO FRASES
  Serverless: sem pedido, sem custo.
  IaC: infra escrita se refaz; infra clicada se perde.
  IAM: cada função recebe só o que usa.
  CORS: quem bloqueia é o navegador; quem libera é a API.
  CI/CD: quem publica é a esteira, e só o que passou no teste.
