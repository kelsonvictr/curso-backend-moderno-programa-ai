HTTP é o protocolo usado nesta conversa entre navegador e servidor. A resposta traz um código de status: 200 significa que a chamada foi atendida com sucesso.

Uma requisição é um pedido enviado à aplicação. GET é o método HTTP usado aqui para buscar uma resposta. A rota /ola indica qual resposta queremos. Vamos criar uma única entrada: GET /ola.

🧑 Navegador

recebe o pedido→💬 Resposta
API funcionando

Controller é uma classe que atende chamadas HTTP. As marcações com @ são anotações: informações que o Spring usa para reconhecer a classe e a rota.

@RestController
public class OlaController {
    @GetMapping("/ola")
    public String ola() {
        return "API funcionando";
    }
}

Trecho de leitura: o agente colocará package e imports no arquivo. @RestController marca a entrada web; @GetMapping liga GET à rota; return devolve o texto.

ETAPA 4 DE 6 · cerca de 25 min

Combinar o que será entregue

Agora queremos: escrever uma especificação curta do cadastro antes de gerar seu código.

Especificação, ou spec, é a descrição do comportamento que esperamos. É como anotar o pedido do cliente antes de ir para a cozinha. Ela responde: quais dados entram, quais regras valem e como reconhecer uma entrega correta?

SDD significa Specification-Driven Development, desenvolvimento guiado por especificação. Nosso ciclo será: escrever exemplos → conferir o plano → autorizar → executar → comparar o resultado com os exemplos.

Os exemplos usam códigos HTTP: 201 = criado; 422 = os dados foram entendidos, mas violam uma regra; 400 = a entrada não pôde ser interpretada. Os detalhes da chamada POST e do formato JSON serão montados na etapa 5.3.

A pasta .specs/ guardará esses documentos. É uma convenção nossa, não um recurso do Java ou do Spring. O ponto no início faz a pasta ficar oculta em alguns exploradores de arquivos; dentro da IDE ela continua sendo uma pasta comum.

5.1 · Primeiro, a regra: o pedido faz a conta



O domínio é a parte do programa que conhece o assunto do negócio. Na cafeteria, ItemPedido conhece quantidade e preço; Pedido conhece seus itens e calcula o total. Eles podem ser testados sem navegador, Spring ou banco.



Em Java, uma classe reúne dados e comportamentos; um objeto é um exemplar dessa classe. Um teste automatizado executa uma situação e confere o resultado esperado. Para dinheiro usaremos BigDecimal, um tipo decimal, em vez de double, que pode produzir aproximações binárias.



🎙️ Professor · diga assim
“Se eu anotar duas unidades de 18,90 num papel, o total é 37,80. Essa regra existe antes de escolher banco ou site. É ela que vamos proteger.”


Mostre: Um teste construindo um pedido e conferindo o total, sem iniciar a aplicação.


Pergunte: Para descobrir o total, precisamos ligar o PostgreSQL?
Resposta comentada: Não. A conta depende dos itens. Se o teste exigir banco para multiplicar quantidade por preço, misturamos responsabilidades.

5.2 · Depois, o processo: criar e guardar



Um caso de uso organiza uma ação que alguém quer fazer. CriarPedidoService receberá os dados, criará um pedido válido e pedirá para guardá-lo. Ele não precisa saber como o armazenamento funciona.



Pense numa tomada: ela define o encaixe; aparelhos diferentes respeitam esse encaixe. Em Java, uma interface declara operações que uma classe deve oferecer. Chamaremos essas interfaces de portas (ports). Uma classe que realiza a operação de uma porta é uma implementação.



🚪 Porta de entrada: CriarPedido
Define o que a aplicação oferece: criar um pedido. O caso de uso implementa essa interface.




🚪 Porta de saída: Pedidos
Define o que a aplicação precisa: salvar um pedido. A aplicação usa essa interface, sem escolher um banco.






O adaptador (adapter) faz a conexão com uma tecnologia concreta. PedidosEmMemoria implementará a porta Pedidos, guardando os objetos na memória do processo. Ao encerrar a aplicação, esses dados desaparecem.



public interface Pedidos {
    void salvar(Pedido pedido);
}


Leia: “Quem implementar Pedidos precisa saber salvar um Pedido”. void significa que este método não devolve um valor. O caso de uso pode devolver o próprio pedido após salvar.


🎙️ Professor · diga assim
“O caso de uso pede “salve este pedido”. A interface é o contrato desse pedido. A classe de memória executa o trabalho. Depois conectaremos outra classe com o mesmo contrato.”


Mostre: A interface Pedidos e a classe PedidosEmMemoria. Mostre quem pede e quem executa.

Resposta comentada: O adaptador. O caso de uso depende da operação salvar, declarada na porta, e continua igual quando mudamos a tecnologia.

5.3 · Por último, a entrada web



POST é o método HTTP usado aqui para criar. JSON é um formato de texto com campos e valores. O Controller receberá esse texto e chamará a porta CriarPedido.



POST /pedidos
{
  "itens": [
    { "sku": "CAFE-500", "quantidade": 2, "precoUnitario": 18.90 }
  ]
}


Um DTO é um objeto que transporta dados na entrada ou saída. O DTO da web representa o JSON. O Controller o converte para o comando da aplicação. Isso evita que nossas regras precisem conhecer o formato da web.



O Spring montará os objetos numa classe de configuração: cria o armazenamento em memória, entrega-o ao caso de uso e entrega o caso de uso ao Controller. Bean é um objeto administrado pelo Spring; @Bean marca o método que o fornece.

Agora podemos dar nome à organização: arquitetura hexagonal



Construímos um núcleo com regras e casos de uso. Ele conversa com o exterior por portas. Adaptadores conectam essas portas à web e ao armazenamento. Arquitetura hexagonal é essa organização por dentro e fora; o desenho com seis lados não obriga seis camadas nem seis classes.

🐘 PostgreSQL
Um banco de dados que organiza registros em tabelas e os mantém em disco. A aplicação se conecta a ele.






Docker executa o PostgreSQL num ambiente isolado, o container. Docker Compose descreve como iniciar esse ambiente. Um volume guarda os arquivos do banco fora da parte descartável do container.



Porta de rede, como 5432, é um número que identifica onde um serviço atende. Ela é diferente da porta da arquitetura, que é uma interface Java. Healthcheck é uma verificação para saber se o banco está pronto para receber conexões.


JPA é um padrão para mapear objetos Java para registros de banco. O Hibernate implementa esse padrão; Spring Data JPA reduz o trabalho de acesso. Eles ficarão no novo PedidosJpaAdapter, que implementa a mesma porta Pedidos.
