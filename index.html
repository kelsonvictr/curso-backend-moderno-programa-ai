Do código que um sênior espera ver aos sistemas orientados a eventos (RabbitMQ, Kafka) e ao serverless na AWS. O diferencial: você não digita no piloto automático — você escreve a spec, dirige o Claude Code e revisa o que ele gera.

Escrever código virou commodity. Julgamento, não.

A IA já escreve a sintaxe. O que o mercado paga é a habilidade de reconhecer código bom, nomear por que é bom, e cobrar isso de quem — ou do que — escreve. Por isso este curso inverte o seu papel: o Claude Code gera; você revisa contra SOLID, padrões e arquitetura.

PedidoService.java · PR aberto por 🤖 claude-code 
+ public class PedidoService {
+   public void processar(Pedido p) {
+     validar(p); salvarNoBanco(p);
+     enviarEmail(p); gerarNotaFiscal(p);
+     atualizarEstoque(p); logarAuditoria(p);
+   }
+ }

Você · revisor
Uma classe fazendo validação, persistência, e-mail, fiscal, estoque e auditoria? Isso viola SRP. Quebra em colaboradores e deixa o PedidoService só orquestrando. Refatora.

Um sistema que atravessa o curso: Pedidos & Pagamentos
Nasce hexagonal, com Postgres no Docker, no Sáb 1. Chega aqui no Sáb 8.

Um pedido é criado, o pagamento é aprovado (ou não), o estoque baixa, a nota fiscal é gerada, o cliente é avisado. Simples de entender — e cheio dos problemas certos: e se o e-mail cair, o pedido falha? E se a mensagem de pagamento chegar duas vezes, cobra dobrado?
